# Data Model

Every object and field this project adds to the org. Built from the metadata in `force-app` by `tools/data_model.py`; do not edit this file by hand. Record each change in `docs/data_model_log.md` and rerun the script.

**Fields on existing objects** (CQ managed objects and standard objects) are listed first: they change objects this project does not own, so they need care on upgrade and when moving between orgs.

## Change log

Newest first. Add a line here whenever an object or field is created, changed or removed, then run `python3 tools/data_model.py`.

### 15 Nov 2026
- **New object Investigation Evidence** (`Investigation_Evidence__c`, IEV-0000): evidence for a hypothesis or a why on the Find the Cause step. Fields: Investigation (lookup), Hypothesis (lookup, related list Evidence), Why (lookup to CQ's Why), Kind (Test, CQ Record, Ask CQ.AI), Test Type (Measure or Inspect, Compare, Reproduce, Remove the Cause, Check Records), Supports (For, Against, Inconclusive), Status (Planned, Done), Detail, Result, Record Id, Record Name, Owner (User), Due Date, Done On. Files attach to the record.
- **Investigation Hypothesis**: added How Do You Know? (becomes the CQ root cause's Justification), Is Not Fit (JSON: which Is / Is Not rows it fits or does not), Five Why Tool (lookup to the CQ 5 Why investigation tool made for it), Root Cause (lookup to the CQ root cause it was saved as).
- **Root Cause** (CQ object, our field): Cause Role (Primary, Contributing). There can be more than one Primary.
- **5W2H, Investigation Tool, Why** (CQ objects, no new fields): Find the Cause writes the Is / Is Not into CQ's 5W2H (Is and Is Not in each field) and each hypothesis's 5 Why into a CQ 5 Why tool with its Why records.
- **Nonconformance** (CQ object, our fields): Repeat Of (lookup to the earlier NC), Repeat Decision (Escalate to CAPA, Link to Earlier CAPA, Not Needed), Repeat Decision Reason. Set at Complete Triage when the same problem happened before after a CAPA closed. Escalate also sets CQ's Initiate CAPA; Link sets CQ's Related CAPA to the earlier CAPA. A closed CAPA is never reopened.
- **Investigation Not Relevant**: added Nonconformance (lookup, related list Triage Not Relevant), set when triage marks the earlier NC Not the Same Problem; the NC's investigation honours it later. Investigation is now empty on those rows.
- **New object Investigation Hypothesis** (`Investigation_Hypothesis__c`, HYP-0000): a possible cause tested in the CQ.AI Investigation workspace. Fields: Investigation (lookup to CQ Investigation), Number (H1, H2 ... within the investigation), Hypothesis, Category (CQ's root cause categories), Status (Open, Confirmed, Ruled Out), Source (name), Source Record Id (the CQ change order, document, deviation or calibration it came from), Investigation Change (lookup). Made by Add as Hypothesis on the What Changed step; Find the Cause will confirm or rule them out and save confirmed ones as CQ root causes.
- **New object Investigation Change** (`Investigation_Change__c`, IC-0000): a change added by hand on the What Changed step (not held in CQ). Fields: Investigation (lookup), What Changed, Change Date, Category (CQ's root cause categories plus Other), Where Found, Link or Reference.
- **New object Investigation Not Relevant** (`Investigation_Not_Relevant__c`, INR-0000): a past record the investigator marked Not Relevant on the Check History step, so it drops off the list for that investigation. Fields: Investigation (lookup, related list Not Relevant Records), Record Id (18), Record Name, Reason. Restore deletes it.

### 14 Nov 2026
- **CAPA (CQ object `compliancequest__SQX_CAPA__c`)**: added Field Action (lookup to Field Action, relationship CAPAs) and the record type **CAPA - Field Action** (`CAPA_Field_Action`). A field action's Closure step creates a skeleton CAPA of this type (title, part, field action, Target Due Date 60 days out) and links it back in the field action's CAPA field.
- **Field Action**: Other Records is no longer shown on the Closure step (the field stays for now). The CAPA check blocks closing only until a CAPA is linked; the CAPA's own status does not hold the field action open.
- **New object Lot Stock** (`Lot_Stock__c`): units of a lot on hand at a CQ Location, one record per lot per location, loaded from the ERP. Fields: Lot (Lot Info lookup), Lot Number, Location (CQ Location lookup), Units On Hand, As Of, Source (ERP, Manual). `LotStockTrigger` fills Lot Number from the lot and keeps open field action lots up to date. Eleven test records (Source Manual) were added in dev for the FA-0001 lots and a few others.
- **Field Action Lot**: Units On Hand and Location are now filled from Lot Stock (Location is a text summary of the CQ Locations) and are no longer typed on the Scope step; Units Shipped is read-only there too. Logic in `CqLotStock`.
- **Activity (standard Task and Event) — existing object**: added Recall Task Type, Field Action Customer (lookup), Lot Number, Units. Field action work is tracked as standard Tasks on the Field Action; return and destruction task units add up to the lot's Returned and Destroyed, and a completed Collect response marks the customer Acknowledged.
- **Field Action Customer**: Status now follows the customer's Collect response task; Follow Ups is no longer used (follow-ups are tasks).
- **Field Action Lot**: Units Returned, Destroyed and Corrected now add up from the units on the lot's recall tasks (lots whose tasks carry no units keep the figures typed before). The Recovery step no longer edits them directly. Logic in `CqFieldActionTasks`.
- **New object Lot Shipment** (`Lot_Shipment__c`): units of a lot shipped to a customer, loaded from the ERP. Fields: Lot, Lot Number, Customer, Units, Ship Date, Ship To, Contact Name, Order Number. A trigger keeps Units Shipped on open field action lots equal to the shipments.
- **Field Action Customer**: added Customer (Account lookup) and Source (Shipment, Added by hand). Customers now fill from the lot shipments.
- **New object Field Action Customer** (`Field_Action_Customer__c`): customers in a field action's effectiveness check.
- **Field Action Lot**: added Units Returned, Units Destroyed, Units Corrected.
- **Field Action Hold**: added Disposition, Disposition On.
- **Field Action**: added Recovery Status, Verdict, Next Step, Verdict By, Verdict On, Closure Summary, CAPA, Other Records, Closed By, Closed On.
- **New object Field Action Hold** (`Field_Action_Hold__c`): holds on finished and component lots placed by the Strategy step.
- **Field Action**: added Depth, Customer Instruction, Key Message, Check Level, Check Percent, Check Method, Check By, Strategy Status, Strategy Confirmed By, Strategy Confirmed On.
- **Field Action**: added Scope Confirmed By, Scope Confirmed On; Scope Status gained Confirmed. Field Action Lot: Approved In Scope relabelled Confirmed In Scope.
