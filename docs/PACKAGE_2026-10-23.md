# Scout Agent package, 23 Oct 2026 (no eNBA)

Last updated 23 Oct 2026, 8:40 am CT. All 24 PhrTemplateReportTest methods pass in dev.

Everything built for the Scout (PHR) Agent, **except** the eNBA Complete Triage work.

## What is in it
- Lead package, tick-box picker (`phrLeadSelect`) and lead lists (`phrLeadLists`): Most Relevant / Less Relevant / Set Aside, 5 per page.
- Agent works from the Complaint, its Product History Review, a CQ Task or an Investigation (`PhrRecordContext`).
- PHR Summary: generated without the AI-draft line, saved to the complaint, the PHR's Summary field, and copied to the primary investigation.
- Report PDF:
  - from a complaint or PHR: **Product History Report** with the PHR Summary;
  - from an investigation: **Customer Report** with the Investigation Summary, on the investigation and the complaint;
  - Report Date in the header; records worth reviewing start on a new page; older templates (PHR-TEMPLATE-001) are updated on the fly.
  - No "lead" wording anywhere in the report: the note under 2. Summary reads "Next steps and data gaps only. The records are listed in section 3.", and the reasons, summary sentence and footer say "records".
  - The Customer Report prints the Investigation Summary as written: the PHR Report Setting summary checkboxes do not apply to it. (They still shape the PHR Summary when the agent writes it.) The manufacture date window still decides which records are listed.
- Missing Data: no checklist check; reads the complaint description for missing details.
- Scout Checklist: `PhrChecklistAction` + `phrChecklist` card.
- Permission set `PHR_Lead_Access` now also grants `PhrChecklistAction`.
- Agent scripts: `PHR_Agent_Script_TickList_v24.txt` and `Scout_Checklist_Agent_Script_v1.txt` (dev and AI Competition copies are identical).
